AdvFab 开源 · Apache-2.0

可以推理的网络证据。

AdvFab 是先观察、供应商中立的 Kubernetes 网络证据控制器。它把 Linux、Cilium、FRR、DNS、Gateway API 与声明的拓扑事实转化为版本化的观测资源，从不把缺失的证据显示成健康。

回答什么

四个问题，都用证据回答。

采集器产生版本化的测量，测量成为有范围的证据，只有兼容的证据才参与评估。

01

可达性

哪些网络路径当前可达且新鲜？

NetworkPathAssessment 资源记录状态、范围与观测时间。

02

来源

哪些证据支撑一次路由或调度决策？

每个评估都引用它所依据的测量。

03

不确定性

哪些维度未知、过期、不完整或互相矛盾？

缺失的证据报告为未知，绝不被补成健康。

04

影响

一次单独授权的变更，是否改善了同一测量范围？

O / S / I 模型把观测到的结果与对变更的假设分开。

稳定边界

它只负责证据，其他组件保留各自权威。

消费者使用 CRD 和公开的 Observation API，不读取内部 ConfigMap，也不依赖 release 名称、命名空间或 UI。

AdvFab 负责

  • 测量定义 · 符号、单位、范围、窗口与不确定性
  • 有界采集 · 来自 Linux、Cilium、FRR、DNS 与 Gateway API
  • 观测资源 · networking.advfab.org 下的版本化 CRD
  • 受控变更 · 仅在明确授权时执行

留给原有系统

  • Kubernetes、Cilium、FRR · 保留各自的生命周期与权威
  • 路由器与 DNS 提供商 · 配置从不被接管
  • 遥测存储 · 任意指标后端
  • Headlamp 客户端 · 独立安装、独立发布

安装

公开默认值全部关闭。

Chart 不包含任何私有清单或凭据。用评审过的 values 文件开启观测；变更保持关闭。

  1. 把签名的 OCI Chart 安装到独立命名空间。
  2. 用评审过的 values 文件开启观测（applyEnabled: false）。
  3. 用 kubectl 或 Headlamp 插件查看评估结果。

# 安装（默认不开启观测）
helm upgrade --install advanced-fabric \
  oci://ghcr.io/advanced-fabrics/charts/advanced-fabric \
  --version 1.0.0-rc.14 \
  --namespace advanced-fabric --create-namespace \
  --values my-values.yaml

# 查看证据
kubectl get advancedfabrics.networking.advfab.org
kubectl get networkpathassessments.networking.advfab.org

开源云产品家族

三份可以组合的合约。

AdvFab 生产路径证据，Public Edge 用它回答 DNS，Among Clusters 让集群互联而不共享密钥。RE8CH Cloud 以托管服务形式运行这三者。

AdvFab

Kubernetes 网络证据控制器。

开源 Public Edge

健康感知的公共入口与权威 DNS。

开源 Among Clusters

面向 BYOC 服务的主权集群互联。

开源 RE8CH Cloud

基于这些项目构建的托管集群网络。

托管

公开建设。

AFEP 记录标准决策，一致性声明绑定不可变制品，发布附带签名、来源证明与 SBOM。AdvFab 独立治理，不是 CNCF 项目。
